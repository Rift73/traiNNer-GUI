# Supervised train/validation splits

Call `studio.supervised_split.split_supervised_dataset(body, destination, *, root, progress=None, cancelled=None)`. Supply a new destination under an existing private directory outside the image and mask roots. The worker publishes both membership files and `split.json` together using the same no-overwrite rename as the paired SR preparer.

Pass the source training recipe as `body["yaml"]`, an integer `seed`, and a `validationFraction` strictly between 0 and 1. The worker selects `datasets.train` and preserves the recipe's class/category order. It also writes `recipe.yml`, replacing the training set and adding the generated validation set. The validation section uses the shared split preparation rules to omit training crops, augmentation and batch options. The generated recipe keeps other named datasets. The split covers only the new partitions. Model settings, paths and training options come from the supplied recipe. Source-relative options elsewhere in the recipe still use the normal trainer working directory.

Alternatively pass `task`, `dataset` (the train dataset options), and `task_options` in place of `yaml`. This form returns the sections to use in an existing recipe. For either form, `datasets`, `task_options`, `manifests`, `manifestSha256`, `reportPath`, `counts`, `imageIdentity` and `notes` are in the result. YAML requests additionally return `recipePath` and `recipeDatasetKeys`. Images and masks are read from their original paths throughout.

| Task and disk provider | Membership and labels |
| --- | --- |
| `image_classification`, `ClassFolderDataset` | One or more ordered image roots. The first directory below each root supplies the class name. Each original class must appear in `task_options.class_names` and remain represented in train. The result lists counts for both sides in configured ID order. |
| `semantic_segmentation`, `ImageMaskDataset` | One mask root per image root. Full relative stems must match uniquely under the ordinary folder selector. A manifest records the exact two filenames, including their extensions. The original mask supplies its class IDs. Preserve `class_names`, `ignore_label` and the normal training crop. |
| `object_detection`, `CocoDetectionDataset` | One image root plus `annotation_file`. Each output is an ordinary COCO document. It retains category order, raw image/annotation IDs, fields, empty images and ignored records. The trainer uses `task_options.categories` order for foreground labels. Unknown top-level tables require their own partition rules and are rejected. |

Class and mask datasets use `meta_info` pointing to UTF-8 JSON Lines. Each row has a one-based `root` index into the declared roots and an `image` path relative to that root. Image/mask rows also have a relative `mask`. For example, `{"root":1,"image":"scene/a.jpg","mask":"scene/a.png"}`. The loader reads rows in their saved order. An existing supervised membership file can itself be the source for a split. Keep the root order when moving data and update recipe paths. COCO subsets use the original image root. The task inspector and leakage audit follow the same split membership.

## Assignment and evidence

`groupBy` accepts `sample` (default), `parent` (full relative parent), or `scene` (top-level directory). The shared client's `pair` spelling also selects sample grouping. Directory grouping excludes the top-level class label and joins matching directory names across roots and classes. Direct children share the group `.`. These modes require directory names that actually identify the desired scene or subject.

The worker measures image file sizes, hashes equal-size candidates with the split auditor's streaming SHA-256 reader, and keeps identical encoded input images together, including renamed copies. A reused physical mask also joins its samples. Independently stored masks with the same label values may occur on both sides. Groups connected by multiple identities or scene names are indivisible.

The target is the requested fraction of samples, rounded half-up and bounded to leave both sides nonempty. Seeded assignment uses the paired splitter's relative-name group ranking. Single-class groups receive validation quotas with space reserved for every training class. Groups spanning classes stay intact, with training coverage taking precedence. Counts and notes report the achieved fraction and any absent validation classes. Impossible nonempty splits raise an error before publication.

The worker replays generated memberships, compares observed source file metadata and checks cancellation before publication. The seed, ordered roots, source membership, grouping and encoded identities determine the split. Additional files discovered on a later run can change a newly generated split. A saved membership continues to select its listed names. File versions are checked during preparation and can change afterward.

The identity check covers encoded image bytes. Re-encodings, near duplicates, subjects spanning unrelated directories and later source changes require separate evidence. Preparation checks file membership and COCO box metadata. Image decodability, mask pixel IDs and crop geometry belong to the task-data inspection. Segmentation and detection splits do not balance pixel classes or object categories. Source indices and assignment use memory proportional to selected rows and COCO metadata. Hashing streams payloads. Cancellation is cooperative during selection, hashing and verification. The metadata parser and group sort run synchronously. External providers and LMDB are outside these three disk modes.
